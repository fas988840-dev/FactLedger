## ما الذي يفعله ملف `.github/FUNDING.yml`؟

الملف يخبر GitHub أين يعرض روابط التمويل داخل المستودع. حالته الحالية:

```yaml
github: [fas988840-dev]
custom:
  - "https://github.com/fas988840-dev/FactLedger/blob/main/FUNDING/DONATE.md"
```

معنى ذلك:

1. ربط زر/قسم الرعاية بحساب `fas988840-dev` عند تفعيل GitHub Sponsors للحساب.
2. عرض رابط خارجي نظيف إلى صفحة التبرع التي تحتوي عنوان Solana وروابط Solana Pay.
3. لا يضيف Ko-fi أو Open Collective أو أي منصة غير مُنشأة فعليًا.

الملف لا يستطيع قانونيًا أو تقنيًا:

- إنشاء حساب GitHub Sponsors من الصفر بدل مالك الحساب.
- قبول شروط GitHub أو Stripe نيابة عن المالك.
- إدخال الاسم القانوني أو التوقيع أو نموذج W-8/W-9.
- إكمال التحقق من الهوية أو بيانات البنك أو الضرائب.
- ضمان قبول منحة أو تحويل مبلغ من أي جهة.

## خطوات مالك الحساب لتفعيل GitHub Sponsors

تتم هذه الخطوات داخل حساب المؤسس فقط:

1. فتح لوحة GitHub Sponsors.
2. إكمال Profile Details واختيار FactLedger في Featured work.
3. مراجعة Tiers وGoals وPayouts.
4. إكمال تحقق Stripe ونموذج W-8/W-9 بالاسم القانوني والتوقيع وشهادة الإقرار ثم Submit.
5. نشر/إرسال الصفحة إذا ظهر زر النشر أو الإرسال.
6. التأكد لاحقًا بفتح الرابط العام من نافذة خاصة؛ لا نعلن التفعيل قبل أن تتوقف إعادة التوجيه وتظهر صفحة Sponsors فعليًا.

## كيف تعمل المنحة فعليًا؟

المنحة ليست زر دفع عام. المسار الصحيح هو:

1. اختيار برنامج منحة رسمي مفتوح ومناسب.
2. تقديم الطلب من بوابة البرنامج نفسها.
3. انتظار قرار لجنة البرنامج؛ لا أحد يستطيع ضمان القبول.
4. عند القبول فقط: توقيع الشروط وإكمال KYC/KYB أو الضرائب داخل البوابة الرسمية.
5. تنفيذ تعليمات الدفع الخاصة بالبرنامج، وقد تكون بنكية أو USDC أو طريقة أخرى.
6. توثيق المبلغ عند وصوله فعليًا، وعدم إعلانه قبل التحقق.

لذلك صُححت الصياغات العامة: التبرع المباشر مفتوح الآن، أما Sponsors والمنح فلهما مساران رسميان منفصلان ولا يصح وصفهما بأنهما مقبولان أو مستلمان قبل حدوث ذلك فعليًا.
